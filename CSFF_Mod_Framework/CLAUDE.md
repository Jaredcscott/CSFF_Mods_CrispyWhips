# CSFFModFramework — Internal Developer Notes

These rules apply when editing `CSFFModFramework/` source. Content mod authors need only the summary in the root `CLAUDE.md`.

## Framework Scope
Handles: JSON loading, WarpData resolution (incl. nested arrays), sprite/audio/localization, DataMap, perk injection (target group + removal from wrong groups; `"CharacterPerkPerkGroup": "None"` = keep out of all groups, for runtime-granted in-run perks), blueprint tab injection (`BlueprintTabs.json`), ProducedCards normalization, AlwaysUpdate, OverrideEnvironment clearing on perks, spawn trigger evaluation (`CardData/Trigger/*.json`), quest attachment (`Quests.json`), character rosters (`Characters.json`), encounter guards (`EncounterGuards/*.json`).

Internal component notes:
- WarpResolver handles both `Array` and `List<T>` field types (e.g. `PerkGroup.ContainedPerks` is `List<T>`).
- PerkInjector gets `ContainedPerks` FieldInfo per-object type — `PerkTabGroup` and `PerkGroup` are different types. Mixing FieldInfo crashes with `ArgumentException`.
- **BlueprintInjector must use live UI tabs, not only load-time caches.** Hook `BlueprintModelsScreen.Show` as a **postfix** (not prefix — tab tree isn't populated yet); recurse `SubGroups`; reset the `Resources.FindObjectsOfTypeAll(CardTabGroup)` cache each call. `AllData` has 0 tabs at UI time; `Database.GetAllOfType` returns 111; `FindObjectsOfTypeAll` returns 150.
- `BlueprintContainerSaveLoadFix` uses `_isInGameplay` to separate save-load from gameplay. During save load, the postfix on `SpawnDefaultContainedBlueprints` is a no-op (DeferredRun handles it after `OnGMInitialized`). **NEVER reintroduce a synchronous drain in `SpawnDefault_Postfix`** — freezes when ModCore is installed.
- `CardScaleCompat` defers ALL Harmony patching into a coroutine — NEVER call `SafePatcher.TryPatch` for game types during `Awake`.
- `ReflectionCache.FindType` must NOT cache null. Handle `ReflectionTypeLoadException` from `asm.GetTypes()` — use `rtle.Types`, don't swallow.
- `CreateInstanceSafe` MUST initialize serializable class fields (e.g. `LocalizedString`) — WikiMod crashes on null `LocalizedString`. Runtime-created tags MUST have `InGameName` initialized.
- **`JsonDataLoader.LoadAll` registers non-`UniqueIDScriptable` objects too (2.13.0+).** Materializing `ScriptableObject/<Type>/*.json` creates the instance via `CreateInstanceSafe` (which correctly uses `ScriptableObject.CreateInstance`, never `Activator.CreateInstance` — the latter is unsupported for `UnityEngine.Object` subclasses) regardless of whether `Type` is `UniqueIDScriptable`. The `else` branch (non-UID) calls `Api.ContentRegistry.Register(obj)` so it lands in `Database`'s per-type + flat name dict — without this the object is a permanent orphan (created, deserialized, named, then undiscoverable by anything). This is also why `WarpResolver` needed **zero** changes to support e.g. `CardData.WeaponMovesWarpData`: `Walk` already resolves any `*WarpData` key generically by reflecting the base field name off the runtime object (`WarpResolver.cs:157-173`) — the missing piece was purely that the referenced-by-name object was never registered anywhere for `Lookup` to find (`WarpResolver.cs:767-781`, the non-UID resolution path: `Database.GetTypedSO` → `AllScriptableObjectDict` → SO name cache, all three backed by the same `Database` registration).
- **`GameSourceModifier` target resolution has a non-UID fallback (2.14.0+).** `GameSourceModifier.ApplyAll`'s standard branch (`Data/GameSourceModifier.cs`) tries `GameRegistry.GetByUid(targetUid)` first, then `Database.AllScriptableObjectDict.TryGetValue(targetUid, ...)` — additive, so existing UID-based `GameSourceModify/` patches are unaffected. This lets a mod patch a shared vanilla non-UID `ScriptableObject` (`WeaponMove`, `DamageType`, `CardTag`, ...) in place: `ApplyPatch` calls `JsonUtility.FromJsonOverwrite` + `WarpResolver.Walk` on whatever `UnityEngine.Object` it's handed, with no type-specific logic, so it needed no changes once the target could be found. Contrast with shipping the same filename under `ScriptableObject/<Type>/` (§Custom Non-UID ScriptableObjects) — that path always creates a NEW instance via `CreateInstanceSafe`; it never mutates an existing one, so it cannot be used to edit a vanilla object that other cards already hold a direct reference to.

## Performance Rules
- **NEVER call `Resources.FindObjectsOfTypeAll` more than once per type.** Reuse `Database.AllScriptableObjectDict` / `Database.SpriteDict` / `Database.AudioClipDict`. Exception: `BlueprintInjector` does a `CardTabGroup` scan at UI time — refreshed on each `BlueprintModelsScreen.Show` (load-time caches are stale there; see Internal component notes), but still only one scan per Show call.
- **NEVER iterate `AccessTools.AllTypes()` with per-type `FindObjectsOfTypeAll`** — call `FindObjectsOfTypeAll<ScriptableObject>()` ONCE and group by `GetType()`.
- **NEVER re-read mod JSON from disk in downstream services** — reuse `JsonDataLoader.JsonByUniqueId` / `JsonDataLoader.AllModUniqueIds`.
- **Cache `AccessTools.Field` lookups by (Type, fieldName).** Repeated reflection over 1,283 cards is slow.
- When accessing `LocalizedString` via reflection, check both field AND property; check `DefaultText` content (default-initialized structs box non-null).
- `Paths.BepInExPath` does NOT exist — use `PathUtil.FrameworkDir` or `PathUtil.PluginsDir`.

## Compatibility Stubs
Framework ships **LitJSON.dll** + **UnityGifDecoder.dll** in `plugins/CSFF_Mod_Framework/`.

- **LitJSON.dll** stub at `CSFFModFramework/Stubs/LitJson/LitJsonStub.cs`, v0.19.0.0. **CRITICAL: namespace MUST be `LitJson` (lowercase j), NOT `LitJSON`** — wrong casing causes `TypeLoadException`. Extend the stub; don't swap to a binary passthrough.
- Framework no longer ships `ModCore.dll`/`ModLoader.dll` stubs. Our mods MUST NOT declare `[BepInDependency]` for `Pikachu.CSTI.ModCore`, `Pikachu.CSFF.ModCore`, or `Dop.plugin.CSTI.ModLoader`.
- All third-party CSFF mods use `ModLoaderVerison: "1.3.0"` — it's the game's manifest schema, not a framework *version* marker. However, framework 2.5.1+ DOES use the field's **presence** for ModLoader-ownership detection: when ModLoader/ModCore is installed, mods carrying it are skipped (the Pikachu loader owns them) — see root `CLAUDE.md` §ModInfo.json.
- **Framework 2.11.1+ reclaims mistagged mods** (`ModDiscovery.DiscoverMods`, `ModManifest.HasFrameworkOnlyMarkers`): a `ModLoaderVerison`-tagged mod that ships a framework-exclusive declarative file (`BlueprintTabs.json`, `SmeltingRecipes.json`, `DropInjections.json`, `InjectImprovementInto.json`, `WorldMap/MapNodes.json`/`FullMap.json`, `EncounterGuards/*.json`, `Quests.json`, `Characters.json`, `WorldMap/HubPortals.json`, `MapMod.json` — none of which ModLoader/ModCore's own loader reads) is loaded by the framework anyway instead of being skipped. This covers mods exported by the ModEditor tool with the Pikachu field stamped in regardless of actual target loader. `ForeignInstanceReconciler` still runs unconditionally and neutralizes the resulting duplicate `UniqueIDScriptable` instances ModLoader creates for these UIDs — do not remove that phase or reorder it relative to `WarpResolver`. Do NOT edit a third-party mod's `ModInfo.json` to work around this — fix mistagging by extending `HasFrameworkOnlyMarkers` in `ModManifest.cs` if a new marker file type appears.

### Detecting third-party mod versions during Awake
`BepInEx.Bootstrap.Chainloader.PluginInfos` is NOT populated for plugins that load AFTER ours. Use `System.Reflection.AssemblyName.GetAssemblyName(dllPath).Version` (doesn't load into AppDomain). Example: `CardScaleCompat.FindCsrDllVersion` scans `Paths.PluginPath` for `CardSizeReduce.dll`.

### When a TargetInvocationException is logged
Use `ex.InnerException?.ToString() ?? ex.ToString()` — `ex.Message` hides the real cause. Before debugging a "known fixed" issue, verify the deployed DLL mtime under `BepInEx/plugins/CSFF_Mod_Framework/` against source — stale deploys produce phantom reproductions.
