## Rules

One table, three resource tiers, one owner per resource. Adding a shared resource means adding a row here
**first**.

- **Tier V (vanilla tag)**: preferred whenever vanilla ships a fitting tag; zero infrastructure, zero
  coordination, immune to load-order and instance-identity hazards. Check the name in
  `Documentation/GameData/CSFF-JsonData_Current/ScriptableObjectObjectName/CardTag.txt`.
- **Tier X (interop tag)**: a `tag_x_<PascalCase>` CardTag. The `x_` infix marks interop, sorts together, and
  cannot collide with vanilla (`CardTag.txt` contains no `tag_x_*`). Content mods reference it by name only; no
  mod ships a `ScriptableObject/CardTag/` file for it (WarpResolver creates a missing tag once and every mod naming
  it resolves the same instance; IDEAS_OVERVIEW 3.5 annotation).
- **Tier U (presence-gated UID)**: for what tags cannot express (trade rows, alternates, drop or recipe
  injection). Always via ALT, INJ, HIDE or the variants below, never structural.
- **The owner defines semantics** (units, field conventions); participants conform or negotiate a registry
  change. Owner is not gatekeeper: producers self-tag without asking.

## Doctrine amendments (2026-10-09, Fleet plan feature 10)

**(a) Drop-slot variant of INJ.** A foreign UID may sit in a drop slot (`DroppedCardWarpData` in an NPCAction or
AgentAction `DroppedCards`, or a forage/`DropInjections.json` row) when it is in a dedicated per-partner action,
or in a collection whose other entries resolve without the partner. Vanilla's roll skips a null `DroppedCard`
(`.decomp/CardsDropCollection.cs` 356-372: no exception, nothing spawns), so the absent-behaviour test passes.
It is NOT silent: WarpResolver prints one Info line per mod per boot, `WarpResolver: [<mod>] unresolved: ...`
(`CSFFModFramework/Data/WarpResolver.cs:175`), and that line is the only trace a real typo leaves, so it is kept at
Info. Still forbidden: a foreign UID in `RequiredCardWarpData`, `TransformInto`, `CardsOnBoard`, a single-entry
trigger list, or a player-action `ProducedCards`. Amends IDEAS_OVERVIEW 3.3 item 1.

**(b) LIST mechanism.** A foreign UID may sit in an allow-list or weight-row list (an event's
`ExtraDurabilityModifications[].AffectedCardsWarpData`, a SelfTriggeredAction's `CardDropChanceModifiers`) when
either at least one entry of the list always resolves (a vanilla GUID), or a load-time guard disarms the change if
none does. The guard matters because WarpResolver leaves an all-unresolved list at its old value, and
`ExtraDurabilityChange.AppliesToAllCards` reads an empty list as ALL cards. A null weight row adds 0. Proven:
Harsh Wilds' black bear and eagle raid lists (vanilla entries keep them non-empty) and its heron list (all
foreign, disarmed by `HarshWilds/Patcher/HeronRaidGuard.cs`). Adds to IDEAS_OVERVIEW 3.2.

**(c) The IDEAS_OVERVIEW 3.3 item 2 exception (CMC HardDependency on ACT, 2026-08-15) is RETIRED (2026-10-09,
Fleet plan feature 2, Community Mod Chest 1.69.5).** The framework hosts the shared metal parts (Metal Nail,
Metal Sheet, Tin Solder; `Documentation/Design/CSFFModFramework_Content_Update_Round2_As_Built.md` section 31, framework 2.28.0) and
the Market Stall builds from a vanilla chest (Fleet feature 1), so `Community_Mod_Chest/Plugin.cs` no longer
declares the dependency. No content mod may now hard-depend on another: the Fleet plan's end state is no
`[BepInDependency]` between content mods at all (feature 4).
